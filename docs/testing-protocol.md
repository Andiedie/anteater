# 模型测试执行、验收与干预规范

适用于新的 anteater SVG 测试、补测、重测及入库审核。执行干预遵循用户 2026-10-02 的澄清：**等待 Agent 正常结束；允许探索和修正，不能因创建脚本、少量重复操作或运行较久而自动 abort。** 最终入库遵循用户 2026-11-10 的补充：**请求/渠道故障应补跑，不能作为最终失败成绩入库；只有输出预算耗尽等有充分证据的稳定模型失败才最终入库。**

本文定义操作约束；导入和页面数据约定见 [README](../README.md)。旧测试按实际条件保留，不得追溯改写成按新规则运行。

## 1. 一个测试是什么

- 测试键：准确的模型 ID + 调用渠道/上游 + 思考控制 + 运行配置。开关 `on/off` 不等同于离散 effort `medium`。
- 一个 attempt 是一个新目录、一个新 Pi 会话、一个原始绘图 prompt。工具续轮和原会话 XML 修正不是新 attempt。
- 重测、失败后重新发绘图 prompt 是新 attempt，必须有用户授权，不能覆盖旧会话。
- 保存启动命令、Pi/扩展版本、模型与等级、工具集、输出预算、重试/压缩/预热配置、目录和会话 ID。只按该渠道确实支持的控制执行，不从原厂能力反推适配器能力。
- 总耗时、请求耗时、token、费用和异常各自保留。`done` 只表示工作流已结束，不表示测试成功。

## 2. 开始前固定条件

统一原始 prompt，不添加画风指导、建议代码或预先准备的文件：

> Generate an animated SVG of an anteater riding a unicycle while juggling bottles.

用户指定的基础工具集是 **read、write、edit**。创建 Python/JS 文件本身合法；但这个配置没有 bash，Agent 不能执行它们。测试人员不能代跑这些脚本并反馈结果，否则改变了实验条件。若以后开放 bash，应事先确认并作为新工具配置单独标记，不能中途给某个模型额外能力。

- 新目录为空；不加载项目上下文、skills、prompt templates、主题或无关扩展。
- 显式加载所需渠道扩展，以及不向模型添加提示/工具的路由、审计扩展。只记录和执行既定约束。
- 使用独立 `PI_CODING_AGENT_DIR` 和 session 目录；只提供必需的认证，保护私密文件权限。CLI 隔离不是 OS 沙箱。
- 关闭 Agent 自动重试和 provider SDK 重试、cache warming、自动 compaction。禁用配置必须实际核验，不能只依赖命令行干净参数。
- OpenRouter 固定已选上游，`only` 单一值、`allow_fallbacks=false`、`require_parameters=true`；在实际请求处核验模型和 reasoning 参数。
- 不再使用 OpenCode Go 执行测试；原先使用它的模型，后续获准测试改用 OpenRouter 的模型官方上游，并明确记录渠道变化。旧记录保留原渠道；这一迁移规则不自动授权重跑其他模型或等级。
- 输出 token 预算要提前固定并披露，不能因某模型思考慢临时缩小。历史 OpenRouter 批次使用每请求 64,000 token（含思考）；这是历史条件，不等于所有渠道默认值，也不是总会话 token 上限。
- 不设测试总耗时强制截止。不要把 HTTP 首包、网络空闲或上游服务超时当成测试人员的时长限额。`retry.provider.timeoutMs=0` 在已验证的 Pi/OpenAI SDK 路径会立即超时，不可用来表示无限运行。
- 用户未指定新的金额硬上限时，只监控和报告费用；不得私自把任意次数/金额阈值变成新的强制停止条件。

## 3. 正常执行

同一模型的多个已授权档位默认并行运行，无需串行等待（用户 2026-11-11 补充）。每个 attempt 独立配置、进程、工作目录、原生会话和账目；并行 worker 不覆盖共享结果文件。入库、静态构建及预览更新排队执行，避免文件冲突；每档完成后即可入库并提供验收，不必等待其他档位。

1. 提交一次原始 prompt，核验实际 model/level、工具集及上游。输入回执不等于 Agent 已开始；不因暂时没输出重复提交。
2. 等待 Agent 正常执行。读文件、写辅助脚本、改脚本、反复调整 SVG、修正工具调用都是允许的探索。
3. 即使 SVG 已经存在且能解析，也不能提前停止 Agent。让它完成自己的检查和最终回复。
4. 正常结束须同时满足：Agent settled/idle、最后 assistant 的 `stopReason=stop`，且没有未结束的请求或工具链。只有 TUI idle、文件存在、日志 `done` 都不充分。
5. 上游错误、断网、`auth_unavailable`、`length`、abort、监控器故障须单独归类，不伪装成正常完成。请求/渠道故障不是最终模型成绩；在当前已授权模型和档位范围内，排除设施问题或等待渠道恢复后，用全新目录和会话补跑，保留旧 attempt 与账目，不在原会话静默续跑。用户已要求补跑这类故障时，不逐次重复索取相同授权；渠道持续不可用则报告阻塞，不能把请求失败转成已完成入库。

## 4. 允许的反馈

- Agent 自然结束后，测试人员在外部执行固定 SVG XML/安全校验。
- XML 解析失败时，允许向**原会话**原样发送 `xmllint --nonet --noout <filename>` 的错误输出，不追加“请修好”等提示、不代改 SVG。最多三轮，每轮再等 Agent 自然结束。
- 单纯没有 SVG、画得不好、主体不清楚、没有动画，不触发新的绘图提示。按实际失败/未达标记录；请求/渠道故障未交付时遵循第 3 节补跑规则，不能用这条视觉表现规则阻止已授权补跑。
- 安全校验失败不同于 XML 语法失败，不把测试人员的修复建议偷偷混入既定 XML 反馈规则。
- 达到三轮后不再发修正 prompt；已经启动的这一轮仍要等自然结束，不能在它执行中因“轮数到了”abort。
- 后续反馈、工具错误及修正的时间、token、费用均计入该 attempt，同时保留初次交付状态。

## 5. 什么算 OK

分开标记以下状态，不能相互替代：

| 维度 | 判定 |
|---|---|
| 自然完成 | 最终 `stop` + settled，无测试人员中止、监控器关闭或未完请求；真实网络故障不是自然完成 |
| 产物技术通过 | 一个选定的原始 SVG；XML、安全限制、viewBox、大小合格；不包含测试人员代改内容 |
| 画面表现 | 属于模型能力，不作为运行有效性判据；默认不做截图、抽帧、构图、题意或动画效果的视觉验收 |
| 账目完整 | 所有请求均有可核对的 usage/计费证据；未知值保持未知，不当作 0 |

- 自然完成 + 产物技术通过，可列为“执行与技术校验通过”。默认不检查画面，也不把视觉检查列为待完成事项；技术通过不代表画面质量达标。
- XML 修正成功、少量工具错误不自动使测试无效：标“完成，有修正/工具错误”，保留事实，不能据此静默重复挑选更好的结果。
- 有 SVG 但被人为停止：标“人为中止，留有产物”，不能算自然完成，不能按完整成功成绩入库。
- 网络失败、输出预算耗尽、无效 SVG、无 SVG 分别记录。网络、请求、渠道和执行器故障只保留在过程审计中，补跑前撤出最终图库。只有输出预算耗尽等可归因于固定测试条件下模型行为、有充分证据的稳定失败，才按图库失败格式最终入库；单次观察不能写成“已稳定复现”，也不得为证明稳定而擅自扩大付费重测范围。历史故障条目按用户指定范围逐项处理，不自动批量改写。
- 监控器故障是测试设施问题，不是模型能力结论；不得吞掉最后一个请求或借故障直接杀掉仍在工作的 Agent。

## 6. 什么时候干预

### 继续等，不 abort

创建 Python；连续三次修改不同版本的辅助脚本；多次读写；少量 exact-match 编辑失败；耗时超过 20/30 分钟；SVG 暂时不变；思考中没有 SVG。这些现象单独都不能证明死循环。

### 报警、展示证据、优先问用户

连续多个完整请求重复同样的动作/内容，验证结果和相关文件没有实质变化，且 token/费用持续增长：保存调用序列、文件/参数 hash、错误变化、usage 和当前花费，报告“疑似无进展”，而不是直接推断无限循环。

用户没有预先批准硬停止阈值时，普通可疑重复默认只观察。新审计扩展不得使用“第 N 次写文件/第 N 个请求”直接终止；观察计数不是停止授权。

### 可以停止

- 用户明确要求停止，或达到用户事先确认的费用/资源硬上限。
- 有充分证据的长期无进展循环，正在持续产生明显浪费；来不及获得用户回复且损失仍快速增加时，可作紧急止损，并立即报告证据、费用、具体触发原因。不能以三次变化中的脚本写入套用此例外。
- 越权文件访问、错误模型/上游/等级、认证泄漏等安全或实验身份约束被破坏。先阻止违规操作；只有无法安全继续才中止。不得用这类边界保护冒充普通进展判断。

停止必须留下原因和影响：操作者/规则、停止时间、最后一笔请求、当时 SVG、已知/未知费用。先尝试有记录的正常取消，观察请求结算，再关闭终端；不要直接杀掉监控器或 PTY 丢失账单证据。

## 7. 分享、计费、入库

- 会话终止状态明确后，检查完整 session（含 system/tool schemas）不存在凭据或隐私泄漏，再按获准范围使用原生 `/share`；`share.txt` 只写对应会话链接。用户限定仅本地预览时，不执行分享，改为保留逐字节一致的原生 HTML 导出和 JSON 快照，由导入器核对并固定 hash；这些完整会话会进入本地构建，未经另行授权不得提交、推送或部署。
- XML 修正或授权恢复后重新分享，记录新 revision。不能用旧链接声称包含后续过程。
- 只统计所选 branch。思考是输出的子集，不重复加到总 token；缺失思考明细不估算，reported 0 不代表没有内部思考。
- OpenRouter 实扣优先用每笔 generation 的 `total_cost`，与 stream usage 及 key 增量交叉核对。Pi 显示成本可能只是目录估计，不能当实扣；key 有统计延迟和并行消费，差额不得猜分给模型。
- 每次 attempt 自有账本。用户若要重测总花费，另加所有弃用 attempt；不能把重测花费偷偷计入所选会话的模型表现。
- 入库选择、替换和删除须有清单。保留旧会话/原始产物和中止记录；只有明确选用的记录更新图库，不批量把 `done` 转成成功。
- SVG 可以写在运行目录的子目录。验收须递归查找并核对选定文件的实际路径；不得仅查顶层后误报“无 SVG”，也不得为迁就观察器向模型追加路径指导。
- 人为中止后恢复同一会话可以补完产物，但仍标“中止后恢复”，不能消除中止和新增上下文影响。若需要干净、自然完成的基准样本，应在修正规则后另开一个获准 attempt。

### 展示约定

- 同类结果使用相同的摘要、公共事实名称与顺序、解释和证据边界；特殊会话证据放入「补充说明」。全部截断记录、SVG XML 反馈和工具错误均按共享展示规则处理，不给单个模型另设一套公共维度。
- 后续提示总数、已核验 XML 反馈轮数、请求错误和工具错误分开记录；不能将任意追加提示标成 XML 修正，或把错误数推断成重试数。原会话后续轮次仍计入同一 attempt 的时间与用量。
- 分类和补充计数绑定固定公开 revision 或本地原生 HTML/JSON hash。来源变化即失效；缺失证据写「未记录」，不能从报告输出反推请求预算。
- 展示统一由 `scripts/reporting.py` 生成，来源核验见 `content/reporting.json`；原始 SVG、会话、测量值和历史执行条件不追溯改写。双语详情、独立失败页和对比表采用一致术语，具体断流、复现、历史 XML 反馈方式等证据保留在说明或原始来源中。

### 执行合规复核

进一步逐条核对 75 条选定记录、32 条当前图库记录及最新 Pro 重测，发现：

- 为取得无网络异常、自然完成的样本，优先重测五个组合：MiMo V2.6 Pro off、DeepSeek V4.1 Flash high、Grok 4.7 xhigh、MiMo V2.6 Flash high、MiMo V2.6 Pro high。第一项是人为中止；其余四项旧图库会话出现 error 后续跑，分别含 `Stream ended without finish_reason`、WebSocket idle timeout、`terminated`、`terminated`。可保留为历史异常，但不能当无错误样本。
- 早期 42 条 CPA 补测使用全局 agent 配置，没有固定独立配置及显式关闭重试、预热和压缩。范围：GPT 七个模型的 24 条补测、Gemini/Grok 九条重测、Claude 九条选定补测。这 42 条选定会话没有 error、缓存预热 usage 或 compaction 记录；未满足新配置规范不等于证明实际发生污染。
- 用户随后明确接受这 42 条历史启动配置差异，要求按实际结果判断，不机械重跑。已验证全部正常 stop、XML/安全合格、原始 hash 与模型成功 write/edit 一致，真实 Chrome 全部有可见动画。已逐张查看三帧；6 条有瓶子出界或角色/独轮车分离等瑕疵，保留为模型表现，不为挑选更好成绩自动重跑。这 42 条从必要重跑清单撤下；新测试仍采用前述配置保障。
- 旧图库没有统一启动配置快照，15 条缺原始 system 事件；只能标记配置证据不足，不能断言全部符合新配置。旧浏览器 XML 原文反馈与新 xmllint 反馈方式不同，保留历史条件，不视为额外绘图指导。
- Sonnet/Opus max 的 `length` 是预算耗尽的真实失败，不是误杀，不因本次流程整改必需重测。已被新结果替代的 Qwen high、GLM max、MiMo Flash off 不再次重复付费。
